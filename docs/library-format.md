# The model library

The library is the one thing both plugins and both servers agree on. It is a plain folder; there
is no database, no index and no service to keep running.

```
%LOCALAPPDATA%\VRHub\library\
  <slug>\
    meta.json                what the card shows
    scene\
      scene.glb              geometry, materials, embedded textures
      colliders.json         the collision world (segments, surfaces, terrain, spawn)
      railings.json          optional, Revit only: what each railing produced
      textures.json          optional, Revit only: texture scale per material
```

Only entries with **`meta.json`**, **`scene/scene.glb`** and **`scene/colliders.json`** are listed.
A publish writes `meta.json` last, so an interrupted export is invisible rather than a card that
opens a missing scene.

## The slug

A model's identity is its document file name, reduced to a slug: `196 SW-2025` → `196-sw-2025`,
`Casa Árboles` → `casa-arboles`. Re-exporting the same document replaces that folder's contents;
it never creates a second card.

The exact rules (lower-casing, accent folding, separator collapsing, 60-character cap) are defined
once in [`contracts/slug-cases.json`](../contracts/slug-cases.json) and tested in both languages.
If you change them, change that file and both implementations.

Consequences worth knowing:

- Two 3D views of one Revit project are one card; the view name on the card is whichever was
  exported last.
- The same document exported from Revit and from IngeTrazo is also one card — the later export
  wins, because the file name is the key.
- An entry is a **copy**, so walking an older model still works after the source is re-exported.

## meta.json

Schema: [`contracts/library.schema.json`](../contracts/library.schema.json).

```json
{
  "slug": "196-sw-2025",
  "name": "196 SW-2025",
  "source": "revit",
  "sourceLabel": "Revit 2025",
  "fileName": "196 SW-2025.rvt",
  "filePath": "E:\\Models\\196 SW-2025.rvt",
  "view": "Level 1",
  "exportedUtc": "2026-11-08T21:48:15Z",
  "triangles": 323600,
  "generator": "RevitVR"
}
```

| Field | Meaning |
|---|---|
| `slug` | folder name; the URL segment that opens the model |
| `name` | card title. The document name — the plugin's own name is **not** prefixed (the card has a source pill instead) |
| `source` | `revit`, `ingetrazo`, or `other` — drives the pill and the filter tabs |
| `sourceLabel` | e.g. `Revit 2025`; shown on hover |
| `fileName` | source file name including extension, when the host exposes it |
| `filePath` | where it came from; never used to serve anything |
| `view` | Revit 3D view name; `null` for IngeTrazo |
| `exportedUtc` | ISO-8601; the list is sorted by it, newest first |
| `triangles` | for the card; the viewer counts the real number again on load |

## colliders.json

The collision world, derived analytically from the source elements rather than from the render
mesh, so a whole storey of walls costs a few hundred 2D tests. Metres, glTF space (Y up, −Z is
Revit +Y).

| Field | Meaning |
|---|---|
| `segments[]` | `{x1,z1,x2,z2,thickness,y0,y1,solid,sourceId}` — one box per wall run, railing piece or obstacle. `sourceId` names the ElementId for Revit railings |
| `surfaces[]` | walkable planes the ground snap uses: `{y, minX, minZ, maxX, maxZ, p?, h?}` |
| `terrain[]` | sloped ground as triangles, nine floats each; height is interpolated across them |
| `spawn`, `spawnForward`, `eyeHeight` | where the player starts |
| `warnings[]` | what the exporter thought was worth saying — read it first when a model behaves strangely |

A surface's `minX…maxZ` is the bounding box and is only a cheap pre-filter. `p` is the outline as a
flat `[x,z,x,z,…]` polygon, and `h` is a list of holes cut out of it, same format. A floor slab
drawn around a stairwell is exactly that shape: without its hole the slab's box spans the opening,
the ground snap holds the player at storey level over the stair, and the flight cannot be descended.
`tools/floorshape.py <scene> --y <height> --compare` checks the surfaces against the render mesh at
one floor height, so a phantom floor is visible as a number rather than as a complaint.

## HTTP routes

Both servers implement these; `tools/conformance.py` asserts they answer identically.

| Route | Returns |
|---|---|
| `GET /` | the library homepage (`web/index.html`) |
| `GET /viewer.html?model=<slug>` | the viewer, which then loads that model |
| `GET /api/models` | `{ "models": [...], "library": "<path>" }`, newest first |
| `GET /models/<slug>/scene/<file>` | one file from that entry (`scene.glb`, `colliders.json`, …), `no-store` |
| `GET /scene/<file>` | legacy single-scene mount (Revit server only) |
| `GET /api/status` | server status: library path, model count, ports, transport (Revit server only) |

`/api/models` is generated by reading the folder on every request, so an export appears on refresh
and deleting a folder deletes its card. Nothing is cached.

### Guards

`/models/` paths are resolved and checked to stay inside the library; `..`, encoded dots and
separators are refused with 404 rather than normalised into another route. Both servers are tested
for this, including the encoded form that Kestrel otherwise resolves before routing.

## Importing exports made before the library existed

```powershell
python tools/seed-library.py --source revit --name "196 SW-2025" --file "196 SW-2025.rvt" --view "Level 1"
python tools/seed-library.py --source ingetrazo --name "Farnsworth House" `
    --dir "$env:LOCALAPPDATA\IngeTrazo\VR\export"
```

It writes the same `meta.json` a real export writes, so the card behaves normally afterwards.

## Removing a model

Delete its folder. The homepage re-reads the folder whenever it becomes visible or Refresh is
pressed. There is deliberately no delete button in the UI yet.
